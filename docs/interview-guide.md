# 訪談提綱 — V5 IPO 6 欄位 Prompt Guide

> 為 Channel 1（訪談主動萃取）設計。確保訪談內容夠結構化，AI 萃取可用。
> 也適用於 Channel 2 員工自助送件的 Forms 問題設計。

---

## 訪談前 (5 min)

- 介紹此次訪談目的：「集團要建內部 AI 案例專區，希望收錄你/你們部門已落地的 AI 應用」
- 說明後續流程：「我會錄音（或手寫），事後 AI 萃取結構化欄位，DTO 審核後上架到內網」
- 取得錄音同意 + 確認受訪者授權公開（哪些可公開、哪些 internal-only）
- 詢問是否有現成資料（截圖/SOP/簡報）可一併提供

---

## 訪談主體 — 6 欄位對應問題

### 1. Title — 案例名稱
- 「你/你們最近用 AI 解決了什麼問題？能不能用一句話描述？」
- 「如果要把這個案例放上集團網站，標題你會怎麼寫？」

**期望產出**：< 30 字，含「對象 / 動作 / AI 工具」（例：「280+ 財務報表自動化（含 TYM 13 家公司）」）

### 2. Pain Point — 痛點
- 「在用 AI 之前，這件事原本怎麼做？」
- 「最痛的點是什麼？花最多時間 / 最容易出錯 / 最不開心的地方？」
- 「這個痛影響到誰？頻率多高？」

**期望產出**：2-4 句話，包含「誰 / 多久一次 / 痛多重」

### 3. Input — 資料來源與格式
- 「AI 處理什麼資料？來源是哪裡？」
- 「資料格式是什麼？Excel / PDF / 系統匯出 / 人工輸入？」
- 「資料有多少？多大？多頻繁更新？」

**期望產出**：bullet list，3-5 條，每條 < 30 字（例：「各子公司 ERP 系統匯出的 Excel / CSV 報表」）

### 4. Process — 處理流程
- 「AI 做了什麼？一步一步說」
- 「人在哪些步驟介入？為什麼？」
- 「有沒有校驗 / 例外處理 / fallback 機制？」

**期望產出**：bullet list，3-6 步，每步 < 40 字，含「AI 做什麼 + 人做什麼」分界

### 5. Output — 產出形式
- 「AI 產出的最終形式是什麼？檔案 / 報表 / 通知 / API call？」
- 「給誰用？怎麼用？」
- 「有沒有後續工作流？」

**期望產出**：bullet list，2-4 條，每條 < 30 字

### 6. Benefits — 效益
- 「省了多少時間 / 錢 / 人力？」（量化）
- 「品質有沒有變好？怎麼衡量？」
- 「同仁感受怎麼樣？有沒有不爽的點？」
- 「運行多久了？穩定嗎？」

**期望產出**：bullet list，3-4 條，**至少一條有量化數字**（例：「月節省人工作業時間 200+ 小時」、「跨國 13 家公司資料 100% 準確」）

---

## 訪談後 (5 min)

- 詢問證據連結：「有沒有 demo / 截圖 / 報告 / GitHub repo 連結可以放上？」→ 對應 `EvidenceUrl`
- 詢問適合的 Category（給看 AI Empowerment Deck Type 1×6 + Type 2×4 10 類）→ 對應 `Category`
- 詢問希望標 Stage：Prototype / Development / Deploy → 對應 `Stage`
- 確認案例 Owner（誰是 DRI）→ 對應 `Owner`

---

## 反例（避免）

- ❌ 不要問「你覺得 AI 怎麼樣」這類抽象問題（萃取拿不到結構）
- ❌ 不要只問「你做了什麼」（會漏 Pain Point 和 Benefits）
- ❌ 不要在受訪者沒準備時催「你給我量化數字」（請對方事後補）
- ❌ 不要錄音前忘記詢問授權範圍
